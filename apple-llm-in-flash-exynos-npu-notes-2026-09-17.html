Exynos NPU · architecture note

LLM in a Flash가 최신 Apple 온디바이스 AI에 남긴 것 — Exynos NPU 개발 관점

DRAM보다 큰 모델을 NAND에 두고 실행하는 문제는 NPU TOPS 경쟁보다 시스템 데이터 이동·라우팅·QoS 설계의 문제다.

2026-09-17 · 공개 자료 기반 기술 검토 · 제품 내부 구현은 추정하지 않음

판정: 원 논문의 문제 설정은 Apple의 최신 제품 모델 아키텍처에 명시적으로 계승됐다

공개 확인 사실. Apple은 AFM 3 Core Advanced(온디바이스 200억 파라미터 희소 모델)의 전체 가중치를 NAND에 저장하고, 요청에 맞는 expert만 DRAM에 적재한다고 밝혔다. 한 요청에서 활성화되는 파라미터는 10~40억 개다. 이는 LLM in a Flash의 “DRAM을 초과한 LLM을 flash에서 가중치 스트리밍으로 실행”한다는 핵심 목표와 직접 맞닿아 있다.

다만 Apple이 원 논문의 windowing 및 row-column bundling을 그대로 제품에 사용한다고 공개한 적은 없다. 최신 구조는 IFP 기반 sparse expert, shared expert, 프롬프트 단위 expert 선택이라는 더 상위의 데이터 이동 최소화 방식이다.

개발 우선순위: NPU 단독 최적화가 아니라 SoC 실행 경로

1. Storage → DRAM → NPU 파이프라인

병목은 MAC이 아니라 NAND 지연·대역폭 변동, 메모리 복사, DRAM 대역폭 경쟁이 될 수 있다. NPU가 I/O와 독립적으로 놀지 않도록 double-buffering, asynchronous DMA, expert prefetch를 runtime 수준에서 묶어야 한다.

2. Prompt-level routing

Apple의 공개 설계는 토큰 단위 교체가 NAND에 부적합하다고 명시한다. router가 요청 초기에 expert set을 정하고, 생성 중 드문 재선택만 수행하도록 만들면 random I/O를 예측 가능한 batch read로 바꿀 수 있다.

3. Shared weights의 배치

항상 활성인 shared expert와 attention/KV 관련 텐서는 DRAM/NPU 접근성이 좋은 영역에 상주시킬 후보다. streamed expert와 물리적으로 분리해 eviction이 공통 경로를 훼손하지 않게 해야 한다.

4. 컴파일러 ABI

expert를 독립적인 loadable segment로 취급하고, alignment·tile shape·양자화 그룹이 NAND block 및 NPU tensor layout과 함께 설계돼야 한다. 사후 변환은 I/O locality를 깨기 쉽다.

실험 설계: TOPS 대신 아래 지표를 같이 봐야 한다

  1. TTFT / TPOT 분리: 첫 expert 적재 비용과 steady-state decode 비용을 따로 보고, router 재선택 시 p50/p95/p99 stall을 기록한다.
  2. 전송 효율: 요청당 NAND bytes, useful-weight bytes, read size 분포, contiguous-read 비율, cache-hit rate를 수집한다.
  3. DRAM 경쟁: NPU, GPU, CPU, ISP가 동시에 동작하는 모바일 시나리오에서 DRAM bandwidth와 QoS tail latency를 계측한다.
  4. 전력/열: 단기 token/s뿐 아니라 NAND read와 DRAM traffic을 포함한 tokens/J, 연속 생성 throttling, storage 열 영향을 비교한다.
  5. 품질-시스템 연동: active-parameter budget과 expert 재선택 주기를 바꾸면서 task quality, TTFT, TPOT, energy를 한 그래프에 올린다.

권장 프로토타입

목표: “온디바이스 20B급 sparse model이 가능한가”가 아니라 “어떤 prompt distribution에서 NAND-streamed expert가 체감 가능한 TPOT와 전력을 유지하는가”를 답한다.

  • shared/routed expert 비율이 다른 작은 MoE 3종을 준비하고, 동일한 활성 파라미터 예산으로 비교한다.
  • no prefetch / router prefetch / oracle prefetch를 비교해 router 예측 오차의 상한을 분리한다.
  • expert를 단일 연속 file layout과 분산 layout에 각각 배치해 NAND read amplification과 TPOT tail을 측정한다.
  • foreground UI·camera·network 부하와 공존시켜 메모리 QoS 정책의 효과를 확인한다.
주의. Apple 공개 자료는 특정 A/M 칩, NPU ISA, NAND controller 정책, cache hierarchy를 밝히지 않는다. 따라서 이를 Apple 칩 기능의 역설계 근거로 쓰면 안 된다. 이 문서는 모델/시스템 아키텍처 차원의 재현 가능한 가설로 한정한다.

짧은 결론

이 흐름은 “더 큰 NPU”보다 storage-aware sparse inference가 모바일 LLM 확장의 다음 경계임을 보여준다. Exynos에서는 NPU의 dense compute 효율을 유지하면서도, NAND-DRAM-NPU 데이터 경로·expert residency·router를 하나의 제품 성능 단위로 공동 최적화하는 것이 핵심이다.
