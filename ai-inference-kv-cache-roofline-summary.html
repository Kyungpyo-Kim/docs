AI 반도체 안에서 일어나는 일들
KV Cache부터 Roofline까지

LLM 인퍼런스가 왜 메모리·대역폭·스케줄링의 문제인지, 그리고 특화 AI 칩이 어디에서 경쟁력을 갖는지 정리한 기술 강의 요약

출연: HyperAccel 이진원 CTO · 게시: 2026-09-01 · 길이: 1시간 44분

한 줄 요약: LLM 서비스의 승부는 단순 FLOPS가 아니라, KV cache를 얼마나 효율적으로 보관·이동·재사용하고, prefill과 decode라는 성격이 다른 작업을 얼마나 잘 분리·스케줄링하느냐에 달려 있다. 이 때문에 AI 인프라는 GPU 단일 체제에서 여러 특화 칩이 결합하는 heterogeneous computing으로 이동한다.

1. 왜 인퍼런스가 핵심 산업 문제가 되었나

수요

토큰 사용량의 폭발

모델 사용량이 급증하면서 훈련뿐 아니라 실제 응답을 만드는 인퍼런스 수요가 데이터센터 증설을 이끌고 있다. 전력과 컴퓨트 공급은 수요를 계속 뒤따라가는 구조다.

경제성

컴퓨트의 단가 압력

매출 성장보다 컴퓨트 투자 증가가 더 빠르면, 인퍼런스 마진·GPU 배분만으로는 부족하다. 결국 토큰당 비용을 낮추는 하드웨어와 서빙 소프트웨어가 중요해진다.

HyperAccel의 Bertha는 이 문제에 대해 HBM 대신 LPDDR을 사용해 전력과 가격을 낮추려는 접근이다. 핵심은 이론 대역폭 자체뿐 아니라, 실제 워크로드에서 그 대역폭을 얼마나 높은 비율로 활용하는가다.

3. KV Cache: decode가 메모리 문제인 이유

Transformer의 attention은 현재 토큰이 앞선 모든 토큰을 참고한다. 이전 토큰의 Key와 Value를 매번 다시 계산하지 않도록 저장한 것이 KV cache다. 계산은 아끼지만, 문맥이 길고 동시 사용자가 많아질수록 저장량이 빠르게 커진다.

KV cache 크기 ≈ 2 × layers × sequence length × KV heads × head dimension × bytes per element
  • 문제: decode마다 현재 토큰의 계산보다, 거대한 모델 가중치와 누적된 KV cache를 메모리에서 읽는 시간이 지배적이 된다.
  • 완화: GQA는 KV head 수를 줄이고, KV quantization은 표현 정밀도를 낮춘다. MLA는 cache 표현 자체를 더 압축한다.
  • 결과: 메모리 용량과 bandwidth가 인퍼런스의 직접적인 서비스 품질·비용 요인이 된다.

4. Arithmetic Intensity와 Roofline

Arithmetic Intensity

이동한 데이터 1바이트당 수행한 연산량이다. 값이 낮으면 데이터를 읽는 시간이, 높으면 연산기가 일을 마치는 시간이 병목이 된다.

Roofline 모델

하드웨어의 최대 연산 성능과 메모리 대역폭을 함께 놓고, 워크로드가 compute-bound인지 memory-bound인지 읽는 지도다.

작업대체로 병목효율을 높이는 방법
Prefill / 큰 행렬 연산Compute병렬 실행, 큰 batch, 높은 연산 활용률
Decode / attentionMemory bandwidthKV 절감, 더 큰 batch, 빠른 메모리·데이터 이동
MoE의 개별 expert낮은 arithmetic intensity 가능성expert별 batch 감소를 고려한 특화 배치

따라서 칩의 "TOPS가 더 높다"만으로는 서빙 성능을 설명하기 어렵다. 실제 배치 크기와 모델 구조, KV 처리 방식이 어느 지점에서 roofline을 만나는지 봐야 한다.

5. 서빙 최적화: 서로 다른 부하를 함께 다루는 법

Continuous batching

요청을 고정 배치 단위로 끝까지 묶지 않고, 끝난 요청을 빼고 새 요청을 즉시 넣는다. 유휴 슬롯을 줄여 decode 처리량을 높인다.

PagedAttention

KV cache를 연속 메모리 하나로 잡지 않고 페이지 단위로 관리한다. 단편화와 과도한 선할당을 줄여 더 많은 요청을 수용한다.

Chunked prefill

긴 prefill을 작은 조각으로 나눠 decode와 섞어 처리한다. 한 요청의 긴 입력이 다른 사용자의 토큰 생성을 막는 현상을 줄인다.

Speculative decoding

작은 draft 모델이 여러 후보 토큰을 미리 만들고, 큰 모델이 묶어서 검증한다. 순차적인 decode 횟수를 줄이는 방식이다.

Prefill–Decode Disaggregation

prefill용 pool과 decode용 pool을 분리해 각자의 하드웨어·스케줄링 목표를 최적화한다. 다만 KV cache를 두 pool 사이로 넘기는 비용이 생기므로, 고속 네트워크와 KV 전송·저장 전략이 함께 필요하다.

6. Agentic AI가 만드는 다음 병목

에이전트는 한 번 묻고 한 번 답하는 챗봇보다 긴 작업 흐름을 만든다. 도구 호출, 사람의 확인 대기, 반복적인 문맥 복귀가 늘면서 KV cache의 유효 기간과 재사용 가능성이 핵심 운영 문제가 된다.

  • 골든타임: 사람이 응답하거나 외부 도구가 끝날 때까지 KV를 GPU 메모리에 계속 붙들어 두면 비싸다.
  • 계층형 메모리: 재계산보다 KV를 CPU 메모리·SSD·원격 저장소에서 빠르게 가져오는 편이 나을 수 있다.
  • 캐시 관리: 어떤 KV를 유지·압축·내보내기·폐기할지 결정하는 것이 모델 품질과 인프라 비용을 함께 좌우한다.

7. 결론: 단일 GPU 시대에서 이기종 조합으로

앞으로의 AI 팩토리는 한 종류의 칩이 전부 처리하는 구조가 아니라, GPU·LPU·대용량 메모리·네트워크가 각자 잘하는 구간을 맡는 파이프라인이 될 가능성이 높다.
GPU는 범용적이고 강한 compute를, 특화 칩은 낮은 arithmetic intensity·특정 메모리 패턴·가격·전력 효율의 이점을 제공한다. 핵심은 어떤 모델과 workload에서 어떤 조합이 비용·지연시간·처리량의 최적점을 만드는지다.
