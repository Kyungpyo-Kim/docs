Claude Code, Cursor 등 코딩 에이전트가 RTL 테스트벤치 작성부터 시뮬레이션, FSDB 기반 파형 질의, 검증 결과 이미지 생성까지 수행하도록 하는 실행 가이드와 복사용 프롬프트입니다.

목표와 실행 환경

에이전트는 RTL 사양을 분석하고 테스트벤치와 검증 시나리오를 작성한 뒤, 사용 가능한 시뮬레이터로 실행합니다. 생성된 파형을 wave-mcp 등 실제 파형 분석 도구로 확인하고 핵심 구간을 이미지로 내보냅니다.

  • 시뮬레이터: VCS, Xcelium, Verilator, Icarus Verilog 중 설치·라이선스·기능이 확인된 도구
  • 파형 분석: 사용 가능한 wave-mcp MCP 서버 및 파형 포맷 지원 도구
  • 변환/렌더링: 설치된 fsdb2fst, fsdb2vcd, GTKWave 또는 프로젝트 내 검증된 렌더러
중요한 구현 주의

FSDB 덤프 시스템 태스크($fsdbDumpfile, $fsdbDumpvars)는 보통 Synopsys VCS/Verdi 환경에 의존합니다. Icarus/Verilator 등에서 같은 방식으로 동작한다고 가정하지 말고, 도구별 덤프 포맷·컴파일 옵션을 확인하세요. 또한 아래에 전달된 fsdb2png.py 예시는 임의의 샘플 WaveJSON을 만드는 데모일 뿐 실제 FSDB 신호를 읽지 않습니다. 진짜 파형 검증·PNG라고 보고하지 말고, 파형 데이터 추출과 렌더링을 실제 구현·검증해야 합니다.

표준 검증 절차

  1. 테스트벤치 작성: 사양, reset, 코너 케이스와 프로토콜 타이밍을 확인해 tb_<module>.sv를 작성합니다. 시뮬레이터 호환성에 맞는 덤프 설정을 포함합니다.
  2. 컴파일 및 실행: 실제 환경에 맞는 명령으로 컴파일·실행하고 로그와 종료 코드를 확인합니다. 생성된 파형 파일이 존재하고 0바이트가 아닌지 확인합니다.
  3. 표적형 파형 검증: wave-mcp 세션을 준비하고 주요 신호 천이를 찾은 다음 이벤트 전후 신호값을 질의합니다. 원문 시뮬레이션 로그와 assertion 결과도 함께 확인합니다.
  4. 오류 수정: 기대값과 불일치하면 설계/테스트 조건을 구분해 원인을 찾고 TB 또는 설정을 수정한 뒤 재실행합니다. PASS는 체크포인트가 실제 관측값으로 확인된 경우에만 선언합니다.
  5. 이미지 렌더링: 확인된 신호와 시간 구간을 지정해 실제 파형 데이터에서 PNG를 생성합니다. PNG의 신호·시간축이 검증 구간과 일치하는지 확인합니다.
  6. 결과 보고: PASS/FAIL, 시나리오별 근거, 핵심 타임스탬프·신호값, 실행 환경과 생성 산출물을 보고합니다. 불가능하거나 지원되지 않은 단계는 명확히 표시합니다.

FSDB 덤프 예시

VCS/Verdi처럼 FSDB 시스템 태스크를 지원하는 환경에서 사용할 수 있는 예시입니다. 최상위 테스트벤치 이름과 계층은 실제 프로젝트에 맞게 바꾸세요.

initial begin
  $fsdbDumpfile("wave.fsdb");
  $fsdbDumpvars(0, tb_<module>, "+all");
end

시뮬레이터가 FSDB 태스크를 지원하지 않으면 해당 도구가 지원하는 파형 포맷과 덤프 방식을 사용하고, 포맷 변환 가능 여부를 사전에 확인합니다.

wave-mcp 질의 계획

  1. prepare_session: 생성된 파형 파일을 로드하고 변환·계층 인식 상태를 확인합니다.
  2. get_transitions: 클럭, reset, valid/ready/enable 등 제어 신호의 이벤트 시점을 찾습니다.
  3. read_signal: 각 핵심 이벤트 주변의 데이터 버스, 상태 레지스터, empty/full 플래그 값을 읽습니다.

도구 이름·인자·지원 포맷은 설치된 wave-mcp 서버의 실제 문서 및 스키마를 확인하세요. 도구가 없거나 파일 형식이 지원되지 않으면 그 사실을 보고하고 대체 경로를 사용합니다.

파형 렌더링 스크립트 주의점

요청에 포함된 fsdb2png.py 예시 코드는 아래와 같습니다. 복사해 활용할 수 있도록 문서에 실었습니다. 단, 이 구현은 변환을 시도한 뒤 고정된 샘플 WaveJSON을 렌더링하므로, 실제 FSDB 신호를 읽거나 검증 결과를 시각화하지는 않습니다.

fsdb2png.py 예시 코드 펼치기
#!/usr/bin/env python3
"""fsdb2png.py — 데모용 FSDB→WaveDrom PNG 예시.
주의: 아래 WaveJSON은 실제 FSDB에서 추출한 데이터가 아닌 고정 샘플입니다.
의존성: fsdb2fst, wavedrom-cli
"""
import argparse
import json
import shutil
import subprocess
from pathlib import Path


def run_cmd(args):
    result = subprocess.run(args, capture_output=True, text=True, check=False)
    if result.returncode:
        raise RuntimeError(
            f"Command failed ({result.returncode}): {args!r}\\n{result.stderr}"
        )
    return result.stdout


def convert_fsdb(fsdb_file, output_png, signal_list=None, time_range=None):
    source = Path(fsdb_file)
    if not source.is_file():
        raise FileNotFoundError(source)
    fst_file = source.with_suffix(".fst")
    json_file = source.with_name(source.stem + "_wave.json")

    if not fst_file.exists():
        if not shutil.which("fsdb2fst"):
            raise RuntimeError("fsdb2fst not found; install/configure Verdi tools")
        run_cmd(["fsdb2fst", str(source), "-o", str(fst_file)])

    # DEMO ONLY: replace this fixed sample with values extracted from the
    # actual waveform (e.g. through wave-mcp or a real FST/VCD parser).
    names = [s.strip() for s in signal_list.split(",") if s.strip()] if signal_list else [
        "clk", "rst_n", "valid", "ready", "data"
    ]
    sample = [
        {"name": "clk", "wave": "p........."},
        {"name": "rst_n", "wave": "0.1......."},
        {"name": "valid", "wave": "0..1....0."},
        {"name": "ready", "wave": "0...1...0."},
        {"name": "data", "wave": "x...=.x...", "data": ["0x55AA"]},
    ]
    wave_data = {
        "signal": sample,
        "head": {"text": f"DEMO ONLY: {source.stem} ({time_range or 'All'})", "tick": 0},
    }
    if len(names) != 5:
        raise ValueError("This demo WaveJSON is fixed to five example signals")
    json_file.write_text(json.dumps(wave_data, indent=2), encoding="utf-8")
    if not shutil.which("wavedrom-cli"):
        raise RuntimeError("wavedrom-cli not found")
    run_cmd(["wavedrom-cli", "-i", str(json_file), "-s", str(output_png)])
    if not Path(output_png).is_file() or Path(output_png).stat().st_size == 0:
        raise RuntimeError(f"Renderer did not create a non-empty PNG: {output_png}")
    json_file.unlink(missing_ok=True)
    print(f"[+] Demo image generated (NOT actual waveform data): {output_png}")


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="Demo FSDB to WaveDrom PNG")
    parser.add_argument("input", help="Path to input FSDB file")
    parser.add_argument("-o", "--output", default="tb_result_waveform.png")
    parser.add_argument("-s", "--signals", default="")
    parser.add_argument("-t", "--range", dest="time_range", default="")
    args = parser.parse_args()
    convert_fsdb(args.input, args.output, args.signals, args.time_range)

이 초안은 FSDB→FST 변환이 가능한지 확인하고 WaveDrom CLI 실행을 보여주는 예시용입니다. 실제 파형 PNG가 필요하면 샘플 블록을 wave-mcp/FST/VCD 파서에서 얻은 실제 신호·시간 데이터로 교체하고 검증해야 합니다. 아래 항목도 실환경 적용 전에 구현·확인하세요.

  • 실제 파형 파서/파형 MCP 결과에서 지정 신호와 시간 구간의 값을 추출
  • 지원하지 않는 신호·시간 포맷·누락된 변환기에서 명확히 실패
  • 명령은 shell 문자열 조합 대신 인자 배열로 실행하고 입력 경로를 안전하게 처리
  • WaveJSON 생성 후 렌더러 종료 코드와 출력 PNG 파일을 확인
  • 이미 존재하는 변환 산출물이 오래된 결과인지 확인하거나 재생성 옵션 제공

fsdb2png.py는 실환경에서 파형 기반 구현과 테스트가 끝난 뒤에만 PASS 산출물로 사용하세요.

복사해서 바로 쓰는 사용자 프롬프트

아래 블록을 복사한 뒤, 실제 RTL 파일과 요구 사양을 함께 제공하세요.

아래 RTL 코드와 프로젝트 환경을 바탕으로 자동 검증 파이프라인을 실행해줘.

[입력]
- RTL 파일: fifo.v (첨부 또는 프로젝트 경로)
- 관련 사양/인터페이스: 프로젝트 문서와 RTL을 먼저 확인하고 불확실한 부분은 명시할 것
- 시뮬레이터 및 버전: 설치 상태를 확인해 선택할 것

[요구사항]
1. RTL의 포트, 클럭/리셋 극성, FIFO 깊이와 동작 지연을 확인한 뒤 fifo_tb.sv를 작성할 것.
2. 사용 가능한 시뮬레이터로 컴파일·실행하고, 해당 환경이 지원하는 방식으로 파형을 생성할 것. VCS/Verdi에서 FSDB를 지원하면 wave.fsdb를 생성할 것. 지원되지 않으면 실제 지원 포맷과 제한을 보고할 것.
3. 아래 시나리오를 검증할 것.
   - Reset 해제 후 데이터 0xA1, 0xB2를 연속 Write
   - Write 완료 후 FIFO Empty 신호가 Low로 내려가는지 확인
   - Read 요청 후 출력 데이터가 순서대로 0xA1, 0xB2인지 확인
   - FIFO 인터페이스의 실제 handshake와 출력 타이밍을 RTL 사양에 맞춰 샘플링
4. 테스트벤치에 assertion 또는 명시적 비교를 넣고, 실패 시 종료 코드를 실패로 반환할 것.
5. 생성한 파형을 실제 wave-mcp 도구로 열 수 있는지 확인할 것. prepare_session으로 로드하고 get_transitions로 주요 이벤트를 찾은 다음 read_signal로 이벤트 전후 값을 확인할 것. 도구가 없거나 실패하면 추측하지 말고 실패 사유를 기록할 것.
6. 검증에 성공한 핵심 구간을 정해 실제 파형 데이터로 tb_result_waveform.png를 렌더링할 것. 샘플/고정값을 넣은 데모 이미지로 대체하지 말 것. 렌더링 도구가 없으면 이미지 미생성을 명시할 것.
7. 코드/로그/파형을 근거로 결과를 보고할 것. 실행하지 않은 단계나 확인하지 못한 값을 성공으로 표현하지 말 것.

[최종 보고 형식]
- 판정: PASS 또는 FAIL (근거와 미수행 단계 포함)
- 환경: 시뮬레이터/버전, 파형 도구 및 사용한 변환·렌더링 방법
- 체크포인트: reset, empty, write/read 데이터 순서별 기대값·실측값·판정
- 신호 트레이스: 핵심 타임스탬프와 clk/reset/valid/ready/data/empty 값
- 산출물: 테스트벤치, 로그, 파형 파일, PNG의 경로와 파일 생성 여부
