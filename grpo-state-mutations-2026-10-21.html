한눈에 읽기

어려운 RTL 검증 문제 하나를 모델에게 여러 번 풀려도 전부 실패하면, 무엇을 더 잘해야 하는지 배우기 어렵다. GRPO-SMu는 같은 설계의 서로 다른 버그 변형을 한 학습 그룹에 넣어 성공과 실패의 차이를 만들고, 그 차이로 테스트 계획 생성 모델을 훈련한다.

Abstract · 초록 원문 직접 인용

아래는 Dimple Vijay Kochar, Nathaniel Pinckney, Guan-Ting Liu, Chia-Tung Ho, Chenhui Deng, Haoxing Ren, Brucek Khailany의 논문 원문 직접 인용이다. arXiv:2601.07593v1 · 2026-01-12. 원문 · CC BY 4.0. 번역·요약·생략 없이 옮겼으며 PDF 줄바꿈과 행 끝 분철만 읽기 좋게 정리했다. 기존 한국어 해설과 수치 검토는 별도 설명이다.

RTL design often relies heavily on ad-hoc testbench creation early in the design cycle. While large language models (LLMs) show promise for RTL code generation, their ability to reason about hardware specifications and generate targeted test plans remains largely unexplored. We present the first systematic study of LLM reasoning capabilities for RTL verification stimuli generation, establishing a two-stage framework that decomposes test plan generation from testbench execution. Our benchmark reveals that state-of-the-art models, including DeepSeek-R1 and Claude-4.0-Sonnet, achieve only 15.7-21.7% success rates on generating stimuli that pass golden RTL designs. To improve LLM-generated stimuli, we develop a comprehensive training methodology combining supervised fine-tuning with a novel reinforcement learning approach, GRPO with State Mutation (GRPO-SMu), which enhances exploration by varying input mutations. Our approach leverages a tree-based branching mutation strategy to construct training data comprising equivalent and mutated trees, moving beyond linear mutation approaches to provide rich learning signals. Training on this curated dataset, our 7B parameter model achieves a 33.3% golden test pass rate and a 13.9% mutation detection rate, representing a 17.6% absolute improvement over baseline and outperforming much larger general-purpose models. These results demonstrate that specialized training methodologies can significantly enhance LLM reasoning capabilities for hardware verification tasks, establishing a foundation for automated sub-unit testing in semiconductor design workflows.

1. 코드를 쓰는 능력과 테스트를 생각하는 능력

설계 초기의 작은 RTL 모듈에는 정교한 검증 환경이나 참조 모델이 아직 없는 경우가 많다. 논문은 자연어 명세와 품질을 알 수 없는 RTL을 읽고, 버그를 드러낼 입력과 기대 출력을 생각해 내는 능력을 다룬다. RTL 코드를 잘 생성하는 모델이라도 이런 검증 추론을 잘한다는 보장은 없다.

연구진은 테스트벤치를 곧바로 작성하게 하는 대신 검증 계획을 세우는 일과 실행 가능한 코드로 옮기는 일을 분리했다. 중간 계획을 사람이 읽고 수정할 수 있다는 점도 장점이다. [1, §I·III]

제목의 state는 RTL의 FSM 상태가 아니다. 여기서는 강화학습 모델이 받는 입력, 즉 설계 설명 + 변이 RTL 코드를 뜻한다. State Mutation은 같은 설계에서 버그가 다른 코드들을 입력으로 사용한다는 의미다. FSM 상태 오류는 여러 버그 유형 중 하나일 뿐이다. [1, §IV-B·표 II]

2. 계획 → 테스트벤치 → 시뮬레이션

1단계: 테스트 계획 만들기

모델은 자연어 명세와 RTL 코드를 읽고 다음 네 항목을 정리한다. 명세와 구현의 차이, 그 차이를 드러내는 입력 자극, 올바른 기대 출력, 그렇게 판단한 근거다. 논문이 주로 개선하려는 부분이 이 단계다.

2단계: 계획을 코드로 옮기기

LLaMa-3.1-405B가 계획과 테스트벤치 골격을 받아 구체적인 테스트벤치를 만든다. 생성한 테스트벤치를 정상(golden) RTL과 버그를 넣은(mutated) RTL에 실행해 평가한다. 모델의 글 설명이 그럴듯한지를 보는 데서 끝나지 않고 실제 실행 결과를 확인한다. [1, §III-A–C]

논문 속 파이프라인 레지스터 사례

명세상 inv=1이면 플래그를 반전해야 하는데 구현은 반대로 동작한다고 하자. Fig. 2–3의 계획은 resetn=1, enable=1, inv=1, regWriteFLAG_IN=1, memToRegFLAG_IN=0을 넣고 클록을 가해, 정상 출력이 각각 0과 1인지 확인한다. 데이터와 주소 경로도 함께 검사한다.

이는 논문 예제를 요약한 설명이다. 실제 테스트벤치에서는 reset 시퀀스, 입력 구동 시점, 클록 엣지와 nonblocking assignment 이후의 관측 시점을 명시해야 한다. 그림의 축약 코드를 그대로 실행 가능한 예제로 제공하는 것은 아니다.

평가 지표의 차이: M1은 정상 RTL이 테스트를 통과하는 비율이다. M2는 정상 RTL이 통과하면서 버그 RTL은 실패하는 경우를 센다. 따라서 M2 13.9%를 “정상 테스트 중 13.9%”나 “실제 제품 버그의 재현율”로 읽으면 안 된다. 평가 표본은 500개 원본 설계에서 만든 1,500개 변이 사례다. [1, §III-A·D·V-C]

3. GRPO는 어디서 학습 신호를 잃나

일반 GRPO는 같은 입력에 여러 답을 생성하고 각 답의 보상을 비교한다. 그룹 평균보다 좋은 답을 더 생성하도록 모델을 업데이트한다. 논문 실험에서는 샘플당 8개 답을 생성한다.

advantage = (개별 보상 − 그룹 평균) / 그룹 표준편차

그런데 어려운 문제에서 모든 답의 보상이 같으면 상대적으로 더 나은 답을 가려낼 수 없다. 논문은 이를 advantage가 사라지는 문제로 설명한다. 수식의 표준편차가 0이 되는 경우는 구현에서 별도로 처리해야 하며, 위 식은 알고리즘의 개념 설명이다. [1, §IV-B]

GRPO-SMu는 입력 쪽의 다양성을 늘린다

같은 명세와 원본 RTL에서 출발하되 reset 오류, 경계 조건 오류, 비트 폭 오류처럼 버그가 다른 코드를 그룹에 넣는다. 각 입력에서 테스트 계획을 생성하고, 서로 관련된 입력들의 보상을 함께 정규화한다. 답만 여러 번 뽑는 방식보다 여러 실패 유형을 경험하게 해 보상 차이가 생길 가능성을 높이려는 설계다.

A(s′, a) = [r(s′, a) − 관련 변이 그룹의 평균] / 관련 변이 그룹의 표준편차

해석상 주의: 서로 다른 입력을 비교하므로 보상 차이가 좋은 추론 때문인지 문제 난이도 때문인지도 고려해야 한다. 저자들은 같은 명세와 원본 코드를 공유해 의미 있는 비교가 가능하다고 설명하지만, 임의의 서로 다른 문제를 섞어도 유효하다는 일반적 보장은 제시하지 않는다.

4. 학습 데이터도 가지를 뻗게 만들기

여러 관련 입력을 만들려면 변이 데이터가 필요하다. 연구진은 ScaleRTL의 정상 설계에서 기능이 같도록 의도한 구현 5개를 만들고, 각 구현에 14개 범주의 버그 중 3개 1차 변이를 생성한다. 이후 CVDP 실패 분석에서 만든 71개 세부 연산자로 2차 변이를 만든다. [1, §IV-C]

정상 설계 → 동등 구현 5개 → 구현별 1차 변이 3개 → 추가 변이

동등 구현 후보는 이름·서식, FSM 인코딩, always/case/if 구조, 자원·타이밍 최적화, 계층·신호 재구성 등으로 다양화한다. 버그 범주는 논리 게이트 교체, 신호 반전, 연산자 교체, sensitivity list, 비트 폭 불일치, always 블록 유형, 경계 조건, 타이밍 구문, race condition, 변수 교체, blocking/nonblocking, 인덱스 off-by-one, reset 오류, FSM 상태 손상이다. [1, 표 I–II]

문법이 달라졌는지만 보지 않는다

각 후보는 정상 구현과 함께 설계당 100만 개 무작위 테스트로 실행한다. 관측 출력 차이가 없으면 clean_codes, 차이가 있으면 mutated_codes로 분류한다.

100만 개 테스트에서 차이를 찾지 못한 것을 형식적 동등성 증명과 혼동하면 안 된다. 희귀한 긴 시퀀스나 특정 상태를 놓칠 가능성이 있다. 논문은 기능 검증을 수행했다고 보고하며, 이 확률적 검증의 한계는 실무 적용 시 따로 고려해야 한다.
  • 원본 RTL: 2,452개
  • 동등 구현 후보 + 원본: 14,061개
  • 1차 변이: 17,926개
  • 2차 변이: 22,051개 · 2차 변이용으로 선택한 샘플 1,204개
  • GRPO-SMu 학습 샘플: 1,318개
  • 최종 평가: 원본 설계 500개, 설계당 변이 3개, 총 1,500개 사례

서로 다른 생성·선별 단계의 수치다. 전부 더해 독립된 학습 샘플의 총개수로 계산하면 안 된다. [1, §III-D·IV-C]

5. SFT와 실행 결과 기반 보상

먼저 성공한 예제로 출력 형식을 익힌다

DeepSeek-R1-distill-Qwen-7B를 출발점으로 삼는다. LLaMa-3.1-405B와 Claude3.7-Sonnet으로 계획·테스트벤치를 만들고, 정상 RTL 통과와 변이 검출을 함께 달성한 사례만 SFT 데이터로 채택한다. Claude3.7-Sonnet의 추론 설명을 더해 총 1,902건을 만들었고, 1,521건 학습·381건 검증으로 나눴다. [1, §IV-A]

보상은 정상 회로를 망가뜨리지 않도록 설계한다

R = rₒ + wₘrₘ + rⱼ + r꜀ · 총 0–3점

  • rₒ: 정상 RTL 통과 여부, 0 또는 1
  • rₘ: 변이 검출 비율, 0–1. 단 정상 RTL이 통과할 때만 가중치 wₘ=1, 아니면 0
  • rⱼ: 외부 LLM의 품질 평가, 0 또는 0.8
  • r꜀: 비영어 문자 생성을 억제하는 항목, 0 또는 0.2

아무 RTL이나 실패시키는 테스트가 높은 버그 검출 점수를 받지 못하도록 정상 통과 조건을 앞에 둔다. 다만 전체 보상에는 LLM 평가와 언어 제약도 포함되므로 순수 시뮬레이션 성능 점수와 같지는 않다. [1, §IV-D]

희소한 보상을 다루는 추가 조정

저자들은 token-level loss를 꺼서 짧고 정보가 없는 응답으로 치우치는 현상을 완화했다고 보고한다. 일부 희소 보상 상황에서는 leave-one-out 대신 전체 그룹의 표준편차를 사용해 advantage 계산도 조정했다. 따라서 결과를 입력 변이 하나의 효과로만 단순화하면 안 된다. [1, §IV-E]

주요 설정: SFT 학습률 2e-6, global/micro batch 32/2. RL batch 64, step당 샘플 16개, 샘플당 생성 8개, 학습률 5e-7, temperature 1, KL 계수 0.01. 평가 temperature는 0.7. 설정을 옮긴 것이며 이번 정리에서 학습을 실행하지 않았다. [1, §V-A]

같은 모델로 두 단계를 구성하면 LLaMa는 10.6%p, Claude는 11.3%p 개선됐다. 반면 Claude 계획을 LLaMa가 코드로 옮기는 구성은 Claude 단일 단계 대비 1.7%p 개선이다. “두 단계면 무조건 10–12%p 좋아진다”로 일반화하면 비교 조건을 놓친다.

회로 유형은 원본 500개 중 조합회로 44개(8.8%), 나머지는 순차회로로 분류했다. 분류에는 4개 LLM의 다수결을 사용했다. 순차회로 개선 배율은 본문에서 약 2배, Fig. 8 캡션에서 약 1.6배로 다르게 표현돼 있으므로 하나의 확정 배율로 제시하지 않는다. [1, §V-E]

원문 수치 검토: §V-C는 SFT→GRPO 개선을 8%로 서술하지만 표 IV의 18.2→27.2는 9.0%p다. 본 정리는 표의 수치를 우선하고 차이를 계산했다. 학습 곡선의 보상 개선과 최종 평가의 M1 개선도 별개 지표로 구분했다.

7. 좋은 결과와 남은 제약

  • 아직 실무 검증을 대체할 수준은 아니다. 가장 좋은 구성도 정상 통과율 33.3%, 변이 검출 13.9%다. 저자들 역시 production-ready 검증과는 거리가 있다고 결론 낸다.
  • golden이 전혀 필요 없는 학습은 아니다. 적용 목표는 참조 모델이 없는 초기 모듈의 계획 생성이지만, 학습 데이터 검증·보상·성능 평가에는 정상 RTL을 사용한다. 추론 때의 입력과 학습·평가 기반을 구분해야 한다.
  • 변이 버그와 실제 제품 버그는 다르다. LLM으로 넣은 14개 범주의 버그에서 얻은 성능이다. 실제 SoC 결함, 복잡한 프로토콜, CDC·전력 상태·긴 시퀀스 전반의 성능을 입증한 결과는 아니다.
  • 7B 외의 비용도 든다. 데이터 생성, 100만 회 무작위 테스트, 대형 모델의 테스트벤치 생성·평가가 필요하다. 본문에는 이를 모두 합친 총비용이나 end-to-end 지연의 정량 비교가 없다.
  • 무작위 검증은 놓칠 수 있다. 출력 차이를 관찰하지 못한 변이가 실제로 완전히 동등하다는 보장은 없다.
  • 재현 범위를 넘겨 말하지 않는다. 이번 작업은 전문·표·그림 속 프롬프트를 읽고 정리한 것이다. 공개 학습 코드·체크포인트의 가용성을 확정하거나 학습·시뮬레이션을 재현한 작업은 아니다.

8. 경표의 RTL 검증에 가져온다면

아래는 논문에서 도출한 적용 제안이다. 논문이 검증한 별도 구현이나 실행 결과가 아니다.

바로 적용할 부분은 두 단계 분리

모델을 새로 학습하기 전에도 테스트 계획을 독립 산출물로 남길 수 있다. 명세 조항, 의심 구현, reset·enable·경계값·클록 순서, 사이클별 기대값, 실패 판정 조건을 먼저 검토한 뒤 테스트벤치로 옮기면 사람이 어디에서 잘못됐는지 추적하기 쉽다.

자체 학습을 한다면 변이의 유효성부터 확인

reset 극성, enable 유지, 카운터 경계, 비트 폭·부호, 상태 전이, blocking/nonblocking 등 대상 설계에 맞는 결함군을 정하고, 실제 출력 차이를 일으킨 변이만 학습 신호로 쓰는 편이 낫다. 정상 RTL을 실패시키는 테스트가 보상을 얻지 못하도록 M1 조건을 유지한다.

앞서 읽은 OSS-Fuzz-Gen과 연결되는 지점

앞 논문은 비현실적인 함수 호출이 만든 크래시를 걸러냈다. 이 논문은 정상 회로를 통과시키면서 버그 회로를 구별하는 테스트를 학습시킨다. 두 경우 모두 실패를 많이 만드는 것보다 유효한 실패를 가려내는 기준이 필요하다. RTL에서도 잘못된 reset이나 불법 프로토콜 입력으로 생긴 실패를 진짜 설계 결함과 구분해야 한다.

VI Conclusion and Future Work · 결론 원문 직접 인용

아래는 Dimple Vijay Kochar, Nathaniel Pinckney, Guan-Ting Liu, Chia-Tung Ho, Chenhui Deng, Haoxing Ren, Brucek Khailany의 논문 원문 직접 인용이다. arXiv:2601.07593v1 · 2026-01-12. 원문 · CC BY 4.0. 번역·요약·생략 없이 옮겼으며 PDF 줄바꿈과 행 끝 분철만 읽기 좋게 정리했다. 기존 한국어 해설과 수치 검토는 별도 설명이다.

This work introduces a new task decomposition and proposes a two-stage framework by introducing verbalized test plans as intermediate representations for sub-unit verification. Such test plans not only improve performance, but also enhance the human-in-the-loop control for building better test plans. Our in-depth evaluation and investigation reveals that state-of-the-art LLMs achieve only 15-22% success rates on our hardware verification task despite their strong reasoning and code generation capabilities. To improve them further, we propose an enhanced RL technique, GRPO-SMu, that enhances exploration through input mutation diversity. We also develop a novel tree-based mutation strategy for training data generation for GRPO-SMu. We demonstrate how our GRPO-SMu on a small 7B LLM achieves the best 33.3% golden test pass rate, outperforming other larger and fine-tuned LLMs. While LLMs remain far from production-ready verification, our work establishes crucial foundations for autonomous debugging frameworks to replace manual test creation and improve productivity. Future works can utilize our framework and learnings to develop scalable, deployable systems and agentic workflows, fundamentally reshaping hardware verification to aid faster next-generation semiconductor design.
